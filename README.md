# MeetingFlow

Локальное приложение для командных договорённостей: **встреча → решение → задача → ответственный → срок → результат**. Русский адаптивный интерфейс, постоянная база SQLite, без регистрации и внешних сервисов.

## Запуск

Нужны **Python 3.12+** и **Node.js 22.12+ с npm**. При первом запуске нужен интернет для установки зависимостей.

macOS / Linux, из папки проекта:

```bash
./start.sh
```

Windows:

```bat
start.bat
```

С демонстрационными записями:

```bash
./start.sh --demo
```

На Windows: `start.bat --demo`. Команда демо идемпотентна, не удаляет записи. Остановка обоих серверов — Ctrl+C в терминале запуска. При повторном запуске скрипт распознаёт уже работающий MeetingFlow и выводит его адреса без запуска второй копии. Если порты 8000 или 5173 заняты другим приложением либо запущена только часть MeetingFlow, скрипт сообщает о конфликте до установки зависимостей и запуска серверов. Остановка исходного экземпляра — Ctrl+C в терминале, где он был запущен.

- Приложение: http://localhost:5173
- Swagger: http://localhost:8000/docs
- OpenAPI: http://localhost:8000/openapi.json
- Проверка сервера: http://localhost:8000/api/health

Скрипт создаёт `.venv`, устанавливает Python-зависимости, применяет Alembic-миграции, устанавливает npm-зависимости и запускает оба сервера с проверкой HTTP. Существующая база сохраняется.

## Возможности

- Главная: реальные счётчики встреч, задач, незавершённых и просроченных, ближайшие задачи и последние встречи.
- Создание, просмотр и редактирование встреч; дата, тема до 150 символов, один или несколько участников; поиск и сортировка по дате.
- Участники: справочник и добавление прямо в форме встречи.
- Решения в карточке встречи; несколько задач на одно решение.
- Создание и редактирование задач с обязательными описанием, решением, ответственным и сроком.
- Статусы: «Новая», «В работе», «Выполнено»; фильтры, поиск, сортировка по сроку.
- Просрочка вычисляется по календарной дате, а не отдельным статусом; выполненные задачи не просрочены.
- Карточка задачи содержит кликабельные ссылки на исходные встречу и решение, с прокруткой к решению.
- Валидация рядом с полями, загрузка, обработка ошибок, пустые состояния, уведомление об успехе только после ответа сервера.
- Удаление, авторизация, видеоконференции, AI и корпоративные интеграции в MVP отсутствуют согласно запросу.

## Структура

```text
backend/
  app/
    database.py        # SQLite, сессии и включение внешних ключей
    models.py          # пять сущностей SQLAlchemy 2
    schemas.py         # входная валидация Pydantic
    main.py            # REST API, статистика, обработчики ошибок
    seed.py            # демо-данные
  alembic/versions/    # версионированная миграция схемы
  tests/test_api.py    # автоматическая приёмка и целостность
  requirements.txt
frontend/
  src/
    main.tsx           # React-страницы, навигация и формы
    api.ts             # типы, HTTP-клиент
    styles.css         # Tailwind CSS 4 и адаптивные компоненты
  e2e/flow.spec.ts     # браузерная приёмка Playwright
  public/brand-reference.png # логотип из ТЗ
scripts/start.py       # запуск обоих серверов
start.sh / start.bat
.env.example
```

Frontend: React, TypeScript, Vite, Tailwind CSS, React Router, TanStack Query, Lucide. Backend: FastAPI, SQLAlchemy 2, Pydantic, SQLite, Alembic, pytest.

## Настройки и данные

Без настройки база располагается в **`meetingflow.db` в корне проекта**, путь не зависит от текущего каталога. Для резервной копии остановите приложение и скопируйте этот файл. Не удаляйте его для обновления приложения; схему обновляет Alembic.

Дополнительно скопируйте `.env.example` в `.env`. Относительный `DATABASE_URL` разрешается относительно корня проекта; предпочтителен абсолютный путь `sqlite:////полный/путь/meetingflow.db` (Windows: `sqlite:///C:/путь/meetingflow.db`). `APP_TIMEZONE` по умолчанию `Europe/Moscow`; используется для определения просрочки. При удалённом доступе часовой пояс браузера может отличаться от серверного, поэтому укажите часовой пояс команды явно. На Windows для IANA-часовых поясов устанавливается `tzdata`.

API слушает только локальный интерфейс; frontend проксирует `/api` на порт 8000. CORS разрешает локальные адреса frontend. Это локальная версия без аутентификации, не готовая к публичному размещению с доступом к пользовательским данным.

## Проверки

```bash
cd backend
../.venv/bin/python -m pytest -q
cd ../frontend
npm run build
npm run test:e2e
```

На Windows используйте `..\.venv\Scripts\python.exe`. Браузерные тесты требуют запущенных серверов и установленного Google Chrome (`channel: chrome`). Они создают записи с уникальным временем в используемой базе; для отдельной тестовой базы запустите backend с другим `DATABASE_URL` и примените миграции.

Backend-тесты используют отдельные временные SQLite-базы. Проверяются AC-01–AC-10, негативные запросы, изменение данных, статусы, незавершённые задачи, просрочка на границе текущей даты, сортировка, внешние ключи, запрет потери контекста, идемпотентность демо и совпадение миграции с ORM. Проверка повторного открытия создаёт новое подключение к тому же файлу.

Браузерные тесты проверяют весь пользовательский путь, валидацию форм, редактирование, переход к решению, мобильную навигацию и поведение при серверной ошибке.

Отдельное создание демо (после миграции):

```bash
cd backend
../.venv/bin/python -m app.seed
```

Сборка frontend создаёт `frontend/dist`. Для обычной локальной работы достаточно `start.sh` / `start.bat`; сборка перед dev-запуском не требуется.

## Основные API

| Метод | Путь | Действие |
|---|---|---|
| GET / POST | `/api/participants` | Справочник / добавление участника |
| GET / POST | `/api/meetings` | История / создание встречи |
| GET / PUT | `/api/meetings/{id}` | Просмотр / редактирование |
| GET / POST | `/api/meetings/{id}/decisions` | Решения встречи / создание |
| GET | `/api/decisions/{id}` | Решение с задачами |
| GET / POST | `/api/tasks` | Список / создание задачи |
| GET / PUT | `/api/tasks/{id}` | Карточка / редактирование |
| PATCH | `/api/tasks/{id}/status` | Изменение статуса |
| GET | `/api/tasks/incomplete` | Незавершённые задачи |
| GET | `/api/dashboard` | Статистика и списки |

`GET /api/tasks`: параметры `status=new|in_progress|done`, `incomplete=true`, `overdue=true`, `sort=asc|desc`. `GET /api/meetings`: `sort=asc|desc`. Ошибки валидации возвращают 422 с русскими сообщениями и именами полей, неизвестные записи — 404, нарушение целостности — 409. Создание возвращает 201. Удаление не предоставляется.
