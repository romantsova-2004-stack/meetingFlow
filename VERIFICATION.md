## Критерии приёмки

| Критерий | Выполненная проверка |
|---|---|
| AC-01 | Создание встречи с датой и участником, чтение истории; API + UI |
| AC-02 | Добавление решения, повторное чтение встречи; API + UI |
| AC-03 | Создание задачи из решения с ответственным и сроком; API + UI |
| AC-04 | ID и тексты контекста в API; кликабельная ссылка к решению в UI |
| AC-05 | Изменение и повторное чтение статуса; API + UI |
| AC-06 | «Новая» / «В работе» в незавершённых; API + UI |
| AC-07 | «Выполнено» исключается из незавершённых; API + UI |
| AC-08 | Повторное открытие SQLite и реальный перезапуск backend-процесса |
| AC-09 | Пустые поля, невозможные даты, отсутствие срока/ответственного, недопустимые статусы; API + UI |
| AC-10 | Полный путь от встречи до завершения и восстановления контекста; API + UI |

Дополнительно проверены FR-14 (просрочка, включая срок сегодня и выполненную задачу), FR-15 (сортировка), редактирование встречи и задачи, несколько задач на решение, неизвестные ссылки, внешние ключи и ограничения SQLite, серверная ошибка без ложного подтверждения успеха. В ходе UI-проверки исправлено совпадение ID заголовка диалога и поля темы, нарушавшее доступность подписи.

## Ограничения проверки

- Скрипт Windows подготовлен, но на Windows не запускался: текущая среда macOS.
- Мобильная проверка выполнена в Chrome с viewport 390 × 844; физический телефон и Safari не тестировались.
- Есть предупреждение Starlette о будущем переходе тестового клиента с httpx на httpx2; тесты проходят.
- Серверы локальные, требуют работающего процесса. После завершения сессии окружение может остановить их; повторный запуск: `./start.sh`.
- Тесты UI добавляют записи в используемую базу. Для регулярного запуска рекомендуется отдельная база (см. README).
- Нагрузочные испытания и публичный production-деплой не входят в локальную первую версию.
